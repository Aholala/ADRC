# 第23讲：C++降阶一阶LADRC闭环接入

前置：[第21讲：MATLAB降阶LADRC闭环](21_降阶LESO接入一阶LADRC.md)、[第22讲：C++降阶LESO](22_降阶LESO的C++实现.md)。

**教学归属：工程接入。** 本讲把已有 `adrc::RLESO1` 接入完整的一阶LADRC主机闭环。
不新增公共控制器封装，不改变核心算法，不接TD。
重点是C++自己根据对象反馈算控制，再与独立MATLAB闭环比较。

## 1. 和上一讲有什么不同

第22讲给C++回放预先生成的测量，核对独立观测器。
本讲输入文件只有目标、未知负载、测量噪声和周期；测量来自C++自己的对象。
因此C++控制量会改变对象，新的对象输出又会影响下一拍控制，形成完整闭环。

```mermaid
flowchart LR
    R[调用方速度目标] --> C[一阶反馈与扰动补偿]
    Y[当前速度测量] --> C
    Y --> E[降阶LESO当前扰动重构]
    E --> C
    C --> L[调用方最终限幅]
    L --> P[对象]
    P --> Y
    L --> U[用实际输入推进q]
    Y --> U
    U -->|下一拍q| E
```

对象仍为速度的一阶模型 `y_dot=b0*u+f`。
它不是二阶角度对象，不能替换成第19讲的二阶反馈公式。

## 2. 完整C++在哪里，先读哪几行

打开 `examples/23_reduced_ladrc_integration/control_example.cpp`，先看循环中的编号1～5：

1. 取得当前测量y_meas[k]。
2. `observer.Calc` 使用q[k]和测量重构本拍hat_f[k]。
3. 调用方计算一阶控制请求。
4. 调用方限幅，得到并提交本区间实际输入u_act[k]。
5. `observer.Update` 用同一区间实际输入和当前测量预测q[k+1]。

本拍公式是：

$$
\hat f[k]=q[k]+\omega_o y_{meas}[k]
$$

$$
u_{req}[k]=\frac{\omega_c(r[k]-y_{meas}[k])-\hat f[k]}{b_0}
$$

$$
q[k+1]=q[k]-h\omega_o(\hat f[k]+b_0u_{act}[k])
$$

C++成功路径的重点如下，周围变量由消费工程提供：

```cpp
float f_hat = 0.0f;
if (observer.Calc(measurement, f_hat))
{
    const float requested = (omega_c * (target - measurement) - f_hat) / b0;
    if (std::isfinite(requested))
    {
        const float applied = std::max(-limit, std::min(limit, requested));
        // 在这里提交最终输出。applied应对应所建模型的最终实际输入。
        bool updated = observer.Update(applied, measurement, dt);
        // 消费工程检查updated，并处理各处失败分支。
    }
}
```

`std::isfinite`需要cmath，`std::max/min`需要algorithm。完整例程包含头文件与失败检查，已经编译运行。
主机例程失败时退出程序；实际固件的失败策略由消费工程决定，不能直接套用程序退出行为。
单个模块的失败保持不代表整个“提交输出→状态更新”序列可自动回滚。

只有完成最终输出处理，才知道本区间观测器应使用什么输入。
若有后级功率限制或执行器动态，应继续核对模型输入单位、作用量与时间区间。
不能把前一级控制请求直接当作最终实际输入。

## 3. 什么属于对象，什么属于算法

例程编号6是主机仿真对象：

$$
y[k+1]=y[k]+h(b_0u_{act}[k]+f[k])
$$

区间内u、f恒定，对本讲一阶对象这是精确更新。
对象用double保存速度，传感器侧将“自己的速度加噪声”转为float测量。
观测器和控制请求用float，不直接读取真实f或真实速度变化率。

本例从速度3 rad/s、初始扰动估计0开始。
第一次采到测量后调用Init，令q0=hat_f0-ωo*y_meas0。
实例跨周期保留，不在每次控制循环或目标变化时重置。
非零负载接管时需要另外对齐初始扰动估计与原输入，不能把本例假设当成实机默认值。

CSV、日志和对象推进只属于主机工具，不加入固件控制环。
真正移入消费工程的核心仍只有 `include/adrc/adrc.hpp` 与 `src/adrc.cpp`。
目标、测量、周期、限幅、最终输出和失败策略由消费工程提供。

## 5. 两层对照分别证明什么

**同测量single回放：** 使用C++当前测量、相同float初值、周期、目标和边界，
独立计算当前q、hat_f、请求、限幅与下一拍q，核对五个量逐拍一致。
它检查实现与时序，但这层本身不独立验证对象反馈轨迹。

**独立double闭环：** 自己保存对象与q，使用自己的测量计算控制，不读取C++对象、测量或观测状态。
只有目标、外部负载和噪声序列相同。
它检查完整闭环接线，同时允许float/double舍入与测量量化造成的小差值。

独立double估计还核对消去q后的数学关系：

$$
\hat f[k+1]=(1-\omega_oh)\hat f[k]+\omega_ohf[k]
+\omega_o(n[k+1]-n[k])
$$

另外检查实际输入与观测输入相同、限幅确实发生、对象与q的时间标签、有限数值和末段维持输入。
每组5001行当前采样与预测，对应5000个当前轨迹区间；末行下一拍预测不额外计入限幅时间。

C++的float日志用9位有效数字，足够往返恢复float。
MATLAB先把这些列恢复为float，再转double做物理量比较；
不能直接把十进制日志解析的double与精确float边界比较，否则可能出现纯表示差异造成的极小“越界”。
time、噪声、对象状态按17位有效数字记录，并保留double。
