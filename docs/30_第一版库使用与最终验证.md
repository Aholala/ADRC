第26～29讲已经补齐非线性ESO、两项fal反馈和完整非线性C++接入。

## 1. 库现在有什么

| C++接口 | 对应算法/对象 | 动态状态与用途 |
| --- | --- | --- |
| LTD2 | 线性二阶TD | 平滑值与变化率；r是频率 |
| NLTD2 | 原TD2_NL/fhan | 平滑值与变化率；r是加速度尺度 |
| LESO2 | 一阶对象全阶LESO | 输出、总扰动 |
| LESO3 | 二阶对象全阶LESO | 输出、变化率、总扰动 |
| RLESO1 | 一阶对象降阶LESO | 一个辅助状态q；估计还需当前测量 |
| NLESO3 | 二阶对象三阶非线性ESO | 线性首行、两项fal纠偏 |
| LADRC1 | 一阶LADRC组合 | 内含LESO2 |
| LADRC2 | 二阶LADRC组合 | 内含LESO3；目标位置与零速度基准，无目标速度前馈 |
| NLSEF2 | 原两项fal反馈与显式扰动补偿 | 静态计算，目标变化率由调用方提供 |
| Fal | 共享静态分段幂函数 | 无状态，支持有限正指数，含alpha>1 |

统一头文件为 `include/adrc/adrc.hpp`，也可以按需包含单独头文件。
所有生产源文件在src，均为C++11，无HAL、RTOS、动态内存或时钟读取。
案例里的电流限幅、目标场景、噪声和对象模型不属于公共核心默认配置。

## 2. 从哪条路线开始使用

速度的一阶模型 `y_dot=b0*u+f`，可以从LADRC1开始；需要降阶形式时，按第23讲组合RLESO1与调用方控制律。
角度/位置的二阶模型 `y_ddot=b0*u+f`，可以从LADRC2开始，第19讲有完整线性TD接入例程。
非线性路线使用第29讲的TD、ESO和反馈独立组合，不必因为有非线性实现就优先替换已有线性方案。

这里的模型阶次由所建输入输出关系决定，不是“云台一定二阶、底盘一定一阶”。
例如同一电机的速度环与角度环可能采用不同对象关系；实际b0、反馈单位与符号必须由消费工程确定。

## 3. 接入工程拿哪些文件

最省事是编译src下10个cpp并加入include搜索路径，也可只选需要的模块。
非线性ESO或反馈还需要fal.cpp；完整非线性例程需要fal、nltd2、nleso3、nlsef2四个cpp。
LADRC1/2分别需要对应leso2/leso3实现。

使用CMake时提供目标adrc：

```cmake
# 消费工程控制BUILD_TESTING与ADRC_BUILD_EXAMPLES；固件工程关闭二者。
add_subdirectory(path_to_adrc third_party/adrc)
target_link_libraries(your_firmware PRIVATE adrc)
```

静态库自身不提供单片机启动、链接脚本、调度、设备初始化或执行器选择。
不要把examples里的main、CSV解析、对象推进和主机日志编入固件控制任务。

最小组件声明：

```cpp
#include "adrc/adrc.hpp"
adrc::NLTD2 td;
adrc::NLESO3 observer;
adrc::NLSEF2 feedback;
```

Init配置来自应用。参数例子和调用顺序见第29讲完整已编译源文件，不用额外抄一个未经编译的硬件模板。
固件只初始化一次并跨周期保留状态，模式切换的Reset和失败策略由应用决定。

## 4. 调用时序和单位要明确

当前测量 → 读取本拍TD/ESO状态 → 计算请求 → 最终输出处理并提交 → 用实际输入推进ESO → TD推进。
Update成功后的getter属于下一拍预测，不能拿它冒充尚未采样的当前反馈。
降阶ESO需先用当前q和当前测量Calc重构扰动；NLTD2的Calc返回内部加速度，不能与降阶ESO的Calc混淆。

| 量 | 单位/约定 |
| --- | --- |
| dt、h0 | 秒；dt为真实区间，h0为fhan参数 |
| b0 | 一阶为输出单位/(输入单位·秒)，二阶为输出单位/(输入单位·秒²)，允许负号但须一致 |
| ESO总扰动 | 与所建输出的一阶/二阶导数同单位，不直接等同负载力矩 |
| TD的x2 | TD输入单位/秒；速度输入时它是加速度 |
| delta | 与对应误差尺度一致；改变rad/deg或归一化需要重新换算增益 |

本库bool失败保持是单模块约定，不是整条多模块控制流程的事务回滚。
库检测有限数、参数域与不可表示结果；不能用这些检查替代对象建模、参数选择、闭环稳定性或真实时序验证。
非线性ESO没有通用带宽步长承诺；当前教学配置由第26讲局部矩阵检查。

```powershell

# 或传入自选编译器：-Compiler '完整g++.exe路径'
```

它构建C++11静态库与例程，运行CTest，退出时恢复PATH。
原生CMake也可使用：

```text
cmake -S . -B build/host -G Ninja -DBUILD_TESTING=ON -DADRC_BUILD_EXAMPLES=ON
cmake --build build/host
ctest --test-dir build/host --output-on-failure
```

直接命令需要用户已有可工作的C++编译器PATH；本机MSYS2优先使用上面的脚本。
仅构建生产库时使用 `-DBUILD_TESTING=OFF -DADRC_BUILD_EXAMPLES=OFF`。
